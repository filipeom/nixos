## Objective

Keep the public IPv4/IPv6 address of `vessel-02.filipeom.dev` up to date at OVH
so `cloud`/`plex.filipeom.dev` (CNAMEs to it) always resolve to the household
WAN IP.

## Prerequisites & Safety Checks

- OVH DDNS password exists in `/var/lib/ddclient/password` on `vessel-02`
  (root-only, not in the repo).
- DNS for `filipeom.dev` is managed at OVH.

---

## Procedure

`ddclient` is declarative in `hosts/vessel-02/configuration.nix`:

```nix
services.ddclient = {
  enable = true;
  protocol = "ovh";
  server = "www.ovh.com";
  username = "filipeom.dev-vessel-02";
  passwordFile = "/var/lib/ddclient/password";
  domains = [ "vessel-02.filipeom.dev" ];
  # usev4/usev6 shell one-liners fetch the public addresses
};
```

It runs as a systemd timer (`ddclient.timer`, every 10 minutes) that triggers
the one-shot `ddclient.service`.

### Verify

```sh
systemctl list-timers ddclient.timer
systemctl status ddclient.service
sudo journalctl -u ddclient -n 20
dig +short vessel-02.filipeom.dev @1.1.1.1
```

Expected log line:
`SUCCESS: [ovh][vessel-02.filipeom.dev]> ... IP address was already set`.

### Force an update

```sh
sudo systemctl start ddclient.service
```

### Change the record

Update `services.ddclient.domains` (and username/password if the OVH subdomain
changes), then deploy:

```sh
make deploy-vessel-02
```

## Notes

- The WAN IP is host-independent: `cloud`/`plex.filipeom.dev` only need their
  CNAME pointing at `vessel-02.filipeom.dev`.
- `anchor-01.filipeom.dev` is retired.
- The old Ubuntu procedure (`/etc/ddclient/ddclient.conf`, helper scripts in
  `/usr/local/bin`) no longer applies.
