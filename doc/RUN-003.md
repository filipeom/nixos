# RUN-003: fail2ban and Edge Abuse Monitoring

- **Status:** Active [ Active | Draft | Deprecated ]
- **Target System:** `vessel-02` (active edge), `anchor-01` (observability)
- **Estimated Time:** 5–15 minutes
- **Risk Level:** Low (Medium for ban/unban on the live edge)
- **Related Specs:** [ADR-001](ADR-001.md), [RUN-001](RUN-001.md), [RUN-002](RUN-002.md)

---

## Objective

Operate the edge abuse-prevention stack: fail2ban on `vessel-02` (SSH and nginx
jails), its Prometheus exporter, and the Loki/Alloy log pipeline that feeds the
Grafana dashboards (`Edge Security`, `Edge Traffic`, `Edge Map`).

## Architecture

```
vessel-02
  fail2ban ── journald ─────────────┐
  nginx ── /var/log/nginx/access.log ┤
                                     ├── Alloy ── push ──▶ anchor-01 Loki :3100
  fail2ban-exporter :9191 ◀── scrape ─── anchor-01 Prometheus :9090
                                             └── Grafana (dashboards)
```

- **fail2ban** reads `sshd` from the journal and `nginx-botsearch` from the
  access log. Repeat offenders get longer bans (`bantime.increment`).
- **Alloy** ships `nginx` access logs, `sshd` failures, and fail2ban
  ban/unban events to Loki, enriched with GeoIP (DB-IP Lite).
- **Prometheus** scrapes the fail2ban exporter for jail metrics.

## Prerequisites & Safety Checks

- `vessel-02.local` / `anchor-01.local` reachable on the LAN (off-site: WireGuard).
- The LAN (`192.168.1.0/24`) and WireGuard (`10.100.0.0/24`, `fd00::/64`,
  `fd00:100::/64`) ranges are in `services.fail2ban.ignoreIP` — confirm before
  unbanning/banned experiments.

## Procedure

### 1. Check jail status

```sh
ssh filipe@vessel-02.local
sudo fail2ban-client status
sudo fail2ban-client status sshd
sudo fail2ban-client status nginx-botsearch
```

### 2. Unban an IP (e.g. a false positive)

```sh
sudo fail2ban-client set <jail> unbanip <ip>
# or unban across every jail:
sudo fail2ban-client unban <ip>
```

If the IP is a legitimate client, add it to `ignoreIP` in
`hosts/vessel-02/configuration.nix` and redeploy instead of unbanning it
repeatedly.

### 3. Test a ban end-to-end

```sh
sudo fail2ban-client set sshd banip 203.0.113.5
# verify in Grafana: Edge Security / recent ban events, and the metrics:
curl -s http://192.168.1.111:9191/metrics | grep f2b_jail_banned_current
sudo fail2ban-client set sshd unbanip 203.0.113.5
```

### 4. Inspect logs and the exporter

```sh
# fail2ban's own events
sudo journalctl -u fail2ban.service -n 50

# exporter health, from anchor-01
curl -s http://localhost:9090/api/v1/targets | jq '.data.activeTargets[] | select(.labels.job=="fail2ban")'
logcli --addr=http://192.168.1.124:3100 labels
logcli --addr=http://192.168.1.124:3100 query '{job="fail2ban"} |= "Ban"' --limit=20
```

### 5. Grafana

Dashboards are provisioned from `hosts/anchor-01/dashboards/` into the `Edge`
folder (auto-reload every 30s). Edit the JSON in the repo, redeploy
`anchor-01`, and keep the dashboard as code — UI edits are overwritten on the
next provision.

### 6. GeoIP data freshness

The map uses `pkgs.dbip-city-lite` from nixpkgs. To refresh it with newer data:

```sh
nix flake update nixpkgs     # or a targeted update
make deploy-all
```

## Notes

- **ignore list is the lockout guard.** Never remove the LAN/WireGuard ranges
  from `ignoreIP`; password SSH is already disabled and root login is off.
- Loki retention is **30 days** (`limits_config.retention_period` on
  `anchor-01`); Prometheus keeps 90 days.
- Alloy runs as a `DynamicUser` with the `nginx` supplementary group to read
  `/var/log/nginx/access.log` (mode `0640 nginx:nginx`).
- The fail2ban exporter runs as `root` because the fail2ban socket is
  root-only; it is bound to `192.168.1.111:9191` and never port-forwarded.
- `nginx-botsearch` uses `backend = "auto"` with `logpath` because nginx access
  logs are files, not journald entries.
- To tune sensitivity: `maxretry`/`bantime`/`bantime-increment.maxtime` in
  `services.fail2ban` on `vessel-02`.
