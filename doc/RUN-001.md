# RUN-001: Exposing a new subdomain

- **Status:** Active [ Active | Draft | Deprecated ]
- **Target System:** `vessel-02` (active edge) [Service / Host / Cluster Name]
- **Estimated Time:** 15–30 minutes [e.g., 15–30 minutes]
- **Risk Level:** Low [ Low | Medium | High / Destructive ]
- **Related Specs:** [ADR-001](ADR-001.md), [INV-001](INV-001.md)

---

## Objective

Expose a new HTTP service under a subdomain through the `vessel-02` edge:
public DNS at OVH, split-horizon DNS in unbound, TLS via ACME (DNS-01 at OVH),
and an nginx reverse proxy — all declarative in
`hosts/vessel-02/configuration.nix`.

## Prerequisites & Safety Checks

- OVH API credentials for ACME exist in `/var/lib/acme/ovh.env` on `vessel-02`
  (root-only, not in the repo).
- The backend service is reachable on the LAN and its `<host>:<port>` is known.
- `vessel-02.local` resolves (or deploy from a host with LAN access).

---

## Procedure

### 1. Public DNS (OVH)

Create `SERVICE.filipeom.dev` in the OVH panel as a **CNAME** to
`vessel-02.filipeom.dev` (TTL 3600). `vessel-02.filipeom.dev` is kept current
by `ddclient` (see [RUN-002](RUN-002.md)).

### 2. Internal DNS (unbound)

LAN clients resolve through unbound on `vessel-02`. Add a split-horizon record
in `hosts/vessel-02/configuration.nix`:

```nix
services.unbound.settings.server.local-data = [
  ''"SERVICE.filipeom.dev. IN A 192.168.1.111"''
];
```

### 3. TLS certificate

Add the certificate to the same file:

```nix
security.acme.certs."SERVICE.filipeom.dev" = {
  dnsProvider = "ovh";
  environmentFile = "/var/lib/acme/ovh.env";
  group = "nginx";
};
```

### 4. nginx reverse proxy

Add the vhost:

```nix
services.nginx.virtualHosts."SERVICE.filipeom.dev" = {
  forceSSL = true;
  useACMEHost = "SERVICE.filipeom.dev";
  locations."/" = {
    proxyPass = "http://192.168.1.X:PORT";
    proxyWebsockets = true;
  };
};
```

### 5. Deploy and verify

```sh
make deploy-vessel-02          # or deploy-vessel-02-reboot
curl -I https://SERVICE.filipeom.dev
sudo journalctl -u acme-SERVICE.filipeom.dev.service -n 20
```

## Notes

- Public vhosts terminate TLS on `vessel-02`; backends on `anchor-01` (Nextcloud
  on `:80`, Plex on `:32400`) stay plain HTTP on the LAN. Never port-forward a
  backend directly.
- Services that should stay private need only the unbound record and an internal
  nginx vhost — skip the OVH CNAME and ACME certificate.
- Firewall: `:80`/`:443` are already open on `vessel-02`; if the service listens
  on a new public port, add it to `networking.firewall.allowedTCPPorts` /
  `allowedUDPPorts`.
