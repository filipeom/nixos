## Objective

Move all public ingress from `anchor-01` to `vessel-02` (per
[ADR-001](ADR-001.md)) and rebuild `anchor-01` as an internal, declaratively
managed NixOS data host. All ZFS pool data must remain in place and mounted at
the same paths.

## Scope

**In scope**

- Edge cutover: nginx, certbot, and `ddclient` move to `vessel-02`.
- Backup of all non-pool state on `anchor-01`.
- Fresh NixOS install on `anchor-01`'s NVMe.
- Service restoration on NixOS: Nextcloud (v34, MariaDB), Plex (GPU
  transcoding), NUT, the monitoring stack.
- Documentation updates ([INV-001](INV-001.md), [ADR-001](ADR-001.md)).

**Out of scope**

- Backup/restore architecture (planned ADR-002).
- Internal DNS (already implemented on `vessel-02`).
- VLAN segmentation and the dedicated management node.
- Replacing the `cachepool` disk unless it degrades again.

### DNS (current)

- `cloud.filipeom.dev` and `plex.filipeom.dev` are CNAMEs to
  `anchor-01.filipeom.dev` (TTL 3600).
- `anchor-01.filipeom.dev` is an A record (TTL 60) updated by `ddclient` to the
  household WAN IP.
- The WAN IP is host-independent: moving the edge requires **no DNS change**,
  only the router's port-forward. `anchor-01.filipeom.dev` remains the
  management name for SSH until the management plane moves (ADR-001).

## Target State

- `vessel-02` is the active edge: nginx + certbot (DNS-01, OVH) + `ddclient`;
  it proxies `cloud`/`plex` to `anchor-01` internal listeners.
- `anchor-01` runs NixOS (flake host `anchor-01`), internal-only:
  - Nextcloud 34 (`pkgs.nextcloud34`, `datadir` on `/mnt/hdd`) with MariaDB.
  - Plex with GPU transcoding, `dataDir` on the restored Library.
  - NUT `netserver` for UPS `salicru`; clients on the vessels.
  - Prometheus/Grafana/Loki/etc. as native NixOS modules (ADR-001).
- ZFS pools imported at `/mnt/hdd`, `/mnt/hdd0`, `/mnt/hdd1`.
- No public HTTP listeners on `anchor-01`; the SSH management path is decided
  in Open Questions.

## Constraints and Requirements

1. ZFS pool data is preserved; pools are not created, renamed, or reformatted.
2. Mount paths stay `/mnt/hdd`, `/mnt/hdd0`, `/mnt/hdd1`.
3. File ownership preserved: `filipe` uid/gid 1000, `www-data` uid/gid 33.
4. Nextcloud version must be >= 34 (downgrade unsupported): locked nixpkgs
   provides `nextcloud34 = 34.0.4` (verified).
5. A maintenance window is acceptable; no high-availability requirement.
6. Secrets (OVH API for DNS-01, DB passwords, Plex token, Grafana admin) must
   not land in the repo; interim manual handling until sops/agenix.
7. `anchor-01` must remain recoverable until validation completes.

## Acceptance Criteria

- **Nextcloud:** login, upload/download, desktop sync, no DB errors.
- **Plex:** library loads, playback works, hardware transcoding active.
- **Edge:** `cloud`/`plex` reachable externally with valid TLS; DNS-01 renewal
  proven.
- **NUT:** `upsc salicru` works from `vessel-01`/`vessel-02`; clients shut down
  on low battery (test with `upsmon -c fsd` during the window).
- **ZFS:** all pools ONLINE at identical mount paths after a reboot.
- **Monitoring:** Grafana reachable through the edge, scraping `anchor-01`.

## Risks

| Risk | Mitigation |
|------|------------|
| `cachepool` disk (2010 HDD) fails during migration | Phase 0 scrub/SMART; replace on recurring errors; backup is required regardless |
| Nextcloud downgrade | locked nixpkgs `nextcloud34` matches `34.0.4` |
| Plex metadata permissions / SQLite inconsistency | stop Plex before archiving; restore with the same uid |
| Installer imports or manipulates pools | `zpool export -a` before wipe; verify import afterwards |
| Secrets leak into the repo | interim manual secrets; sops/agenix follow-up |
| Extended downtime | maintenance window accepted; rollback point per phase |
